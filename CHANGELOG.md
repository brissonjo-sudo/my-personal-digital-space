## [Non publié]

### Ajouté
- 2026-11-26 — Étape 7 : passerelle PDF → Markdown. Bouton « Convertir en Markdown » du module PDF : le document tel qu'affiché (pages modifiées, annotations, formulaire rempli) est reconstruit avec pdf-lib puis remis en mémoire au module Convertir (`MPDS.envoyer`), sous son nom d'origine ; aucun téléchargement, rien n'est stocké. Le document reste ouvert dans le module PDF.
- 2026-11-26 — Module PDF, étape 6 : remplir les formulaires AcroForm. **Détection** à l'ouverture et à chaque PDF ajouté, avec PDF.js seul (annotations `Widget` de chaque page ; pdf-lib n'est pas chargé pour l'affichage) : bandeau « Ce PDF contient un formulaire (N champs) » ; XFA pur (XFA sans champs AcroForm, lu dans les métadonnées PDF.js : `isPureXfa` exige `enableXfa`, désactivé ici) signalé « non pris en charge », le document reste visible et annotable ; champs de signature numérique signalés, sans contrôle. **Saisie** : vrais contrôles HTML posés sur la page courante (texte, `textarea` si multiligne, case, radios groupés par nom, liste), positionnés par `coordonnees.js` (rotation et zoom compris), `maxLen` et lecture seule respectés, tabulation de haut en bas ; la couche n'est interactive qu'avec l'outil Sélection (`pointer-events` via le calque voisin), les raccourcis à une lettre restent inactifs dans les champs ; texte hors WinAnsi refusé dès la saisie (le message cite le champ). **Modèle** : valeurs par (source, nom complet du champ) dans `source.valeurs` : elles suivent la page quand on la déplace, la pivote ou fusionne un autre PDF, et un même champ présent sur deux pages partage sa valeur ; bouton « Réinitialiser le formulaire ». **Export** : pour chaque source ayant des valeurs, relecture avec pdf-lib (`password: ''` si chiffré), valeurs appliquées (`setText`, `check`, `select`), texte contrôlé par `MPDS.pdfTexte.verifier`, puis `form.flatten()` avant `copyPages` ; XFA hybride : `deleteXFA()` et avertissement ; une source sans valeur est copiée comme avant ; erreurs nommant le champ. Nouveaux fichiers `formulaire.js` et `formulaire-export.js` ; CSP inchangée. Cache du service worker : `mpds-v6`.
- 2026-11-26 — Module PDF, étape 5 : signature et tampons, aplatis à l'export comme les autres annotations. **Signature** (outil S) : fenêtre modale accessible (focus piégé, Échap ferme) avec deux onglets, *Dessiner* (souris ou stylet, encre noire ou bleu foncé, Effacer) et *Importer une image* (PNG ou JPG ; type réel contrôlé par les octets, 10 Mo maximum, dimensions lues dans l'en-tête avant décodage ; fond clair retiré par seuil de luminosité, curseur de tolérance avec aperçu en direct sur damier). Valider rogne l'image aux pixels visibles, la convertit en PNG (data URL) et passe en mode « placer » (clic = pose, 150 pt de large, proportions conservées). La signature de la session n'existe qu'en mémoire du module : réutilisable pour d'autres poses jusqu'au rechargement, ni `localStorage` ni IndexedDB. **Tampons** (outil P) : Reçu le, Comptabilisé le, Duplicata, Diffusion restreinte, Approuvé, Refusé, Confidentiel, Brouillon, Urgent, Copie ; champ date (JJ/MM/AAAA, jour par défaut) pour les tampons « … le » ; capitales dans un cadre arrondi, rouge (Refusé, Confidentiel, Urgent), vert (Approuvé) ou bleu, incliné de 8° ; texte contrôlé par `MPDS.pdfTexte.verifier`. Les deux types se déplacent et se redimensionnent avec l'outil Sélection (poignée d'angle, proportions conservées, annulable), s'effacent à la gomme et suivent leur page. Export : `embedPng` + `drawImage` pour la signature ; `drawRectangle` (sans remplissage) + `drawText` Helvetica-Bold pour le tampon, avec la rotation de la page. Nouveaux fichiers `detourage.js`, `signature.js`, `tampons.js` ; CSP inchangée (`img-src data:` suffit). Cache du service worker : `mpds-v5`.
- 2026-11-26 — Module PDF, étape 4 : annotations figées dans la page à l'export (pas d'annotations PDF natives). Outils à raccourci d'une lettre, actifs seulement dans le module PDF et hors champ de saisie : Sélection (V : contour, glisser pour déplacer, Suppr), Surligneur (H : opacité réglable, 25 % par défaut), Texte (T : Entrée ou perte du focus valide, Échap annule ; Helvetica, Times ou Courier, taille 18 par défaut ; texte contrôlé par `MPDS.pdfTexte.verifier`, la zone reste ouverte en cas de refus), Dessin (D : épaisseur 3 par défaut), Gomme (E), Annuler (Ctrl+Z) et Rétablir (Ctrl+Y), une pile par document ; palette de 6 couleurs. Les annotations sont rattachées à chaque page du modèle (elles suivent le déplacement, le pivotement et la suppression de la page) et stockées en points PDF (`dePdf` ajouté à `coordonnees.js`) : le zoom et la rotation de l'affichage ne les déplacent pas ; un texte posé sur une page pivotée reste droit. Calque SVG au-dessus du canvas de la page affichée (miniatures sans annotations). Nouveaux fichiers `annotations.js`, `calque.js`, `outils.js` ; `export.js` aplatit les annotations (`drawRectangle`, `drawText`, `drawLine`) sur « Enregistrer le PDF » comme sur « Extraire la sélection ». Cache du service worker : `mpds-v4`.
- 2026-11-26 — Module PDF, étape 3 : gestion des pages. Pivoter (page courante ou sélection), supprimer (jamais la dernière page), réordonner (glisser-déposer des miniatures, boutons monter/descendre au clavier), fusionner (« Ajouter un PDF »), extraire la sélection, « Enregistrer le PDF » (`<nom> (modifié).pdf`), indicateur de modifications non enregistrées et confirmation avant de les perdre. Les pages affichées forment un modèle (`modules/pdf/pages.js`) ; l'export reconstruit un PDF neuf. Bibliothèque d'écriture retenue : `@cantoo/pdf-lib` 2.11.1 (jsDelivr, SRI), chargée à la demande par le nouveau `MPDS.chargerScript` ; seul le fork ouvre un PDF chiffré par mot de passe propriétaire seulement (RC4 40/128 bits, AES-128). Ajout de `modules/pdf/coordonnees.js` (`versPdf`, rotation et CropBox décalée) et `modules/pdf/texte.js` (contrôle WinAnsi : le fork remplace sinon en silence un caractère non pris en charge par « ? »). Cache du service worker : `mpds-v3` (la bibliothèque est mise en cache à la volée).
